# ui识别 素材目录说明

本目录用于存放界面识别的原始测试截图。原始截图约 130MB，且可能包含玩家昵称、战局信息等隐私内容，因此**不随 GitHub 仓库分发**；仓库仅保留 `assets/interface/` 下的 17 张归一化模板、`assets/interface/templates.json` 与本说明。

## 目录结构

```text
ui识别/
├─ 画面识别 <编码> <页面说明>/
│  ├─ 测试图/                       # 16:10 基准截图
│  ├─ 测试图2560 1440 16：9/        # 2560×1440 16:9 实机截图
│  └─ 测试图2560 1600 16：10/       # 2560×1600 16:10 实机截图
└─ 测试画面 H 二级菜单,地图/
   ├─ 测试图/
   └─ 测试图2560 1440 16：9/
```

## 命名与使用规则

1. 一级目录统一为 `画面识别 <编码> <页面说明>`；`H` 沿用历史名称 `测试画面 H 二级菜单,地图`。
2. 分辨率子目录固定为 `测试图`、`测试图2560 1440 16：9`、`测试图2560 1600 16：10` 三种；新增分辨率时按 `测试图<宽> <高> <比例>` 命名。
3. 截图文件按 `{判定字母}{序号}_{得分}.png` 命名，例如 `A8_0.550.png`、`M1_1.000.png`；完整规则见 `测试图命名规则.txt`。判定字母是 `Detector.analyze()` 对整帧的实测结果（不是目录分类字母），得分是驱动该判定的分值。误判样本会带着真实判定字母留在原目录，作为后续修复对照。新旧文件名的对应关系记录在 `测试图命名对照_YYYYMMDD.csv`。
4. 编码与程序界面码一致：`A`–`L`、`M`、`Z`；`0` 表示未识别，不需要素材目录。
5. 修改或新增截图后，运行 `scripts/build_ui_templates.py` 重新生成模板，再运行 `scripts/test_ui_recognition.py` 做回归。
6. 新增截图用 `scripts/rename_test_images.py --incremental` 预览，确认后加 `--apply`：只给新文件分配序号，不改已合规的旧文件名。得分或阈值变化后若要全量重排，直接跑 `--apply`，脚本会先落到唯一临时名再改名，同判定同得分不会互相覆盖。

## 原始截图补传

如确需把原始截图纳入仓库，请先确认隐私与体积，再移除 `.gitignore` 中的 `/ui识别/*` 排除规则并提交图片。默认不分发原始截图。
